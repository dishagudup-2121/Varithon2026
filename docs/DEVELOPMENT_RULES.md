# VARI OS Development Rules

## 1. Versions
All members use the committed Python requirements and frontend package lockfile.

## 2. Branches
- `main`
- `member1/ml-prediction`
- `member2/backend-decision`
- `member3/digital-twin`
- `member4/frontend-i18n`

Never push unfinished experimental work directly to `main`.

## 3. API contract
If an API field changes, update `docs/API_CONTRACT.md` first and tell all members.

## 4. Naming
- Python: snake_case
- TypeScript: camelCase
- API JSON: snake_case
- IDs: stable strings such as `Z6`, `AMB3`, `G001`

## 5. No hardcoded intelligence
Do not hardcode:
- model risk probability
- model accuracy
- recommendation results
- simulation results

Synthetic data is allowed, but outputs must be generated by the implemented logic.

## 6. Simulation honesty
The MVP uses a graph-flow approximation. Do not claim hydrodynamic flood simulation or full pedestrian physics.

## 7. LLM boundary
The LLM is an explanation layer. It cannot directly select routes/resources or override deterministic decision modules.

## 8. Language
Backend data remains language-independent. All UI labels live in:
`frontend/src/locales/en/translation.json`
`frontend/src/locales/mr/translation.json`

## 9. Integration
Every module must expose typed inputs/outputs. Do not pass arbitrary dictionaries between modules when a Pydantic schema can define the contract.

## 10. Pull requests
Before merging:
- backend tests pass
- frontend builds
- API contract still matches
- no secrets committed
